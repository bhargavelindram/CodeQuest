# Professional learning roadmaps

These roadmaps describe the intended depth beyond the five currently interactive introductory lessons. A roadmap topic is not a claim that a reviewed lesson already exists. Add original explanations, tests, labs, accessibility checks and versioned examples before marking a module complete.

## Shared progression

1. **Foundations:** runtime, syntax, values, expressions, input/output.
2. **Control flow:** conditions, loops, tracing, invariants and edge cases.
3. **Functions and decomposition:** parameters, return values, scope, errors and interfaces.
4. **Collections and data modelling:** collection operations, schemas, complexity and validation.
5. **Debugging and testing:** unit tests, boundary cases, test doubles, debugging tools and regression prevention.
6. **Files, packages and APIs:** project layout, dependencies, serialization, HTTP and failure handling.
7. **Algorithms and performance:** searching, sorting, complexity, profiling and trade-offs.
8. **Architecture and collaboration:** modularity, design patterns, Git, code review and maintainability.
9. **Security and reliability:** input validation, secrets, permissions, dependencies, observability and safe failure.
10. **Capstone:** design, implement, test, document and demo a realistic project.
11. **Professional practice:** CI, deployment, accessibility, performance review, portfolio write-up and interview-style explanation.

## Track-specific capstones and focus

| Track | Advanced focus | Capstone direction |
|---|---|---|
| Python | typing, packaging, pytest, async, APIs and data processing | tested CLI/API with structured data and documentation |
| HTML | semantic structure, forms, accessibility and metadata | accessible multi-page site with keyboard testing |
| CSS | responsive layout, cascade, tokens, motion and reduced motion | responsive design system with accessible states |
| JavaScript | DOM, modules, async, fetch, errors and browser security | data-driven application with loading/error states |
| Java | OOP, collections, exceptions, streams, tests and build tools | tested service or command-line application |
| C++ | RAII, STL, ownership, algorithms, build systems and sanitizers | robust algorithmic tool with benchmarks and tests |
| TypeScript | narrowing, generics, module boundaries and runtime validation | typed API client with validated untrusted inputs |
| PHP | HTTP, sessions, database access, validation and secure configuration | small server-rendered app with safe persistence |
| Kotlin | null safety, collections, coroutines and testing | asynchronous data client with clear error states |
| C | pointers, arrays, structs, memory ownership, compilation and sanitizers | bounded parser or command-line utility with tests |
| C# | types, LINQ, async/await, exceptions and .NET testing | tested .NET service or utility |
| Rust | ownership, borrowing, enums, Result, traits and Cargo tests | reliable CLI with structured errors |
| Swift | value/reference semantics, optionals, protocols and concurrency | typed data app with tests and accessible UI concepts |
| React | components, props, state, effects, forms and accessibility | responsive component-based app with tests |
| SQL | relational design, joins, aggregation, indexes and transactions | normalized schema plus tested analytical queries |
| R | data frames, transformations, visual analysis and reproducibility | reproducible analysis report with source data notes |
| Go | interfaces, errors, context, concurrency and testing | HTTP service with tests, timeouts and graceful shutdown |
| Lua | tables, functions, metatables, modules and embedding | modular scripting tool with tests and documented API |
| Roblox Luau | Studio services, events, replication, remotes and server authority | small multiplayer mechanic with server-side validation |

## Completion standard

A professional-level course should contain multiple worked examples, a guided lab, an independent task, automated tests, common wrong-answer feedback, spaced review, a capstone rubric and a reviewed solution. Do not equate a roadmap, generated hint, or self-reported XP with professional certification or employability.
